# Discord requirements research — October 13, 2026

These are official-documentation findings, not live project acceptance. No Discord account action or authenticated provider operation has been performed. Implementation choices below are our design decisions, not Discord guarantees.

| Topic                     | Verified documentation finding                                                                                                                                                                                                                                                                                                                                               | Official reference                                                                                                                             |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| Follow                    | A visible Follow option can relay announcements into a destination server where the user can manage webhooks. Only posts selected for publication arrive.                                                                                                                                                                                                                    | [Channel Following FAQ](https://support.discord.com/hc/en-us/articles/360028384531-Channel-Following-FAQ)                                      |
| Follow edits/deletes      | Published edits propagate; a deleted original can leave a deletion notice. That is not evidence that an event was cancelled.                                                                                                                                                                                                                                                 | [Announcement Channel FAQ](https://support.discord.com/hc/en-us/articles/360032008192-Announcement-Channel-FAQ)                                |
| Bot installation          | Server installation requires the installing human's Manage Guild authority. The bot itself need not receive that permission. User-installed apps are command-oriented.                                                                                                                                                                                                       | [Application installation contexts](https://docs.discord.com/developers/resources/application#installation-context)                            |
| Bot identity              | Bot tokens authenticate the automation account. Standard user-account automation is prohibited.                                                                                                                                                                                                                                                                              | [OAuth2 bot users](https://docs.discord.com/developers/topics/oauth2#bot-users)                                                                |
| Permissions               | View Channel and Read Message History support relay visibility/history reads. Channel overwrites narrow effective access. Their combined invitation bitfield is 66560.                                                                                                                                                                                                       | [Permissions](https://docs.discord.com/developers/topics/permissions)                                                                          |
| Intents/lifecycle         | Guilds and Guild Messages deliver required guild/message events; Message Content supplies content fields. Missing privileged authorization can close the Gateway with 4014. Heartbeats, sequence/session state and Resume are required lifecycle concepts; Resume can replay missed events. Gateway sending is limited; Identify must respect returned session-start limits. | [Gateway](https://docs.discord.com/developers/events/gateway)                                                                                  |
| Current privileged policy | The June 11, 2026 change uses a 10,000-user access threshold, replacing the older 100-server rule. Below it, necessary intents can be toggled locally. At the threshold, intent access requires review; previously reviewed access also has annual renewal. App verification is separate. Never claim the toggle/grant is active without checking.                           | [Current policy update](https://support-dev.discord.com/hc/en-us/articles/40281523410967-Changes-to-Privileged-Intent-Access-for-Discord-Apps) |
| Relay metadata/history    | Message ID is a snowflake. IS_CROSSPOST identifies a followed-origin message; SOURCE_MESSAGE_DELETED marks source deletion. Crosspost references identify the original message/channel/guild. History GET supports bounded before/after/around with limit 1–100 and needs visibility/history permissions. These documented fields still need live observation here.          | [Message resource](https://docs.discord.com/developers/resources/message)                                                                      |
| Follow webhook            | Channel Follower is webhook type 2; source attribution belongs to that provider mechanism. We will not fetch/manage webhooks or store webhook secrets.                                                                                                                                                                                                                       | [Webhook resource](https://docs.discord.com/developers/resources/webhook)                                                                      |
| Update/delete events      | Message update, delete and bulk-delete events exist; delete payloads contain identifiers rather than event-cancellation facts.                                                                                                                                                                                                                                               | [Gateway events](https://docs.discord.com/developers/events/gateway-events)                                                                    |
| Rate limits               | Use returned bucket/reset/retry guidance; do not assume fixed REST request quotas. On 429, honor Retry-After/retry_after, including fractional seconds and global limits.                                                                                                                                                                                                    | [Rate limits](https://docs.discord.com/developers/topics/rate-limits)                                                                          |
| Version/consistency       | API v10 is available. IDs should be strings; events may be missed or delivered more than once, so durable idempotency is required.                                                                                                                                                                                                                                           | [API reference](https://docs.discord.com/developers/reference)                                                                                 |
| Terminal Gateway errors   | Authentication/intent failures must be distinguished from recoverable reconnect cases.                                                                                                                                                                                                                                                                                       | [Opcodes/status codes](https://docs.discord.com/developers/topics/opcodes-and-status-codes)                                                    |

Chosen application scope: one private configured guild, selected destination text channels, read-only bot, Gateway-driven ingestion and capped recovery. No broad server monitor. Proposed intents are Guilds (1), Guild Messages (512) and Message Content (32768), combined 33281. Only Message Content is privileged; do not enable member/presence intents. These choices are justified by unattended content ingestion, not profile access.

Outstanding empirical questions: repeat-read/restart ID stability, crosspost/webhook/reference presence, actual visible text/embeds, edits/deletion delivery and destination permalink use. Do not finalize a composite/original-source identity without evidence. Observe metadata in memory and record only sanitized presence/stability categories; no payload capture. SDK selection and exact recovery/changed-source semantics remain gated in the design/plan.
